# ADR-0007: 使用 PostgreSQL pgvector 作为唯一向量后端

## 状态

已接受

## 决策

正式 MVP 和景区模拟环境统一使用 PostgreSQL 的 pgvector 承载知识与经验向量。ChromaDB 从产品中彻底移除：不进入依赖、镜像、运行时和文档中的当前架构描述，也不随产品提供迁移工具。应用继续通过向量检索 interface 访问后端，以便 MemoryOps 和经验发布流程不感知存储实现。

## 原因

项目的业务事实、版本、发布状态、场地隔离和审计已经以 PostgreSQL 为中心。将向量放在同一数据库可以减少双数据源一致性问题，统一备份和恢复，并让发布事务与向量索引状态更容易核验。当前 Chroma 方案是历史实现，不是本轮景区模拟的目标架构。

## 影响

- PostgreSQL 镜像必须明确安装并启用 `vector` 扩展。
- 知识和经验表需要固定向量维度、索引策略和租户过滤规则。
- 诊断、备份、UAT 证据和文档只报告 pgvector 健康状态。
- pgvector 的数据必须来自正式业务事实表（已发布 `sop_documents`、已发布 `experience_cards`、关闭事件生成的 CASE 记忆），不允许用假向量或合成语料充当业务数据；具体要求见 `docs/vector-data-contract.md`。
- 客户历史 Chroma 数据不属于本产品的迁移范围。若确有客户旧库需要导入，应按客户项目单独评估并重新用本产品的 embedding 模型生成向量，不作为交付前提。
