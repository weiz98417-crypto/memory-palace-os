# ADR-0005: 分离监测信号、态势告警与运营事件

## 状态

已接受

## 决策

系统将外部观测建模为监测信号，将阈值判断结果建模为态势告警，将需要人负责和形成业务证据的处置对象建模为运营事件。告警可以自动恢复；运营事件必须经过责任人处置并由授权人员关闭。

运营事件默认生命周期为 `DETECTED -> TRIAGED -> DISPATCHED -> ACKNOWLEDGED -> MITIGATING -> RESOLVED -> CLOSED`，非法跳转必须被服务端拒绝并记录审计。

## 原因

实时监控的高频、短生命周期数据不应直接污染事件卷宗；同时，真正需要任务、审批和复盘的风险不能停留在不可追责的告警状态。分离后可以让态势层高频刷新，让事件处置层保持稳定和可审计。

## 影响

- 态势快照可以包含大量未转事件的信号和告警。
- 告警转事件必须记录触发规则、来源信号和转换主体。
- 事件关闭不能仅依赖告警消失，必须满足任务、证据和授权条件。
- 前端需要分别展示信号、告警和运营事件，不能只做一张告警列表。
