## 1. 🔍 业务逻辑说明 (Business Logic)

记忆专家是系统的“智库”。与现场指挥官直接下达强制命令不同，记忆专家的核心价值在于**“引经据典”**。它必须基于真实发生过的历史工单或管理规范，提炼出具有指导意义的步骤。

### RAG (检索增强生成) 核心处理链路：
1. **意图承接**: 接收到一线员工关于“怎么处理”、“有过类似情况吗”的询问。
2. **知识打捞 (Retrieval)**: 
   - 将员工的自然语言转化为 1536 维向量。
   - 在 ChromaDB 中进行余弦相似度（Cosine Similarity）检索，召回 Top-3 最相关的历史案例。
3. **幻觉抑制 (Anti-Hallucination)**: 
   - **红线规则**：若检索到的案例相似度均低于 0.78（即毫无相关性），系统必须立刻进行**安全降级**，严禁大模型调用其自身的预训练常识进行编造。
4. **归纳生成 (Generation)**: 将召回的干货案例作为上下文喂给大模型，要求其提炼核心步骤，并附带历史引用。

## 2. 📥 输入契约 (Input Contract)

本智能体依赖于用户的原始提问进行向量化查询。若 `context` 缺少以下核心字段，将拒绝执行：

| 变量名 | 类型 | 必填 | 描述 |
| :--- | :--- | :--- | :--- |
| `raw_text` | String | 是 | 员工的原始提问（用于转化为 Embedding 向量） |
| `intent` | String | 是 | 必须为 `emergency_advice` 才能激活本智能体 |
| `user_id` | String | 否 | 提问者的企微 ID（用于后续权限过滤，暂保留） |

---

## 3. 🧠 决策与生成 SOP (Standard Operating Procedures)

### 🟢 场景 A：成功检索到高相似度历史案例
- **生成原则**: 提炼出 1-3 条核心操作步骤，必须简洁。
- **强制溯源**: 回复中必须显式提及“根据历史记录”或“参考 [时间/案例号]”。
- **语气约束**: 专业、客观、顾问式（"建议您..."，而非命令式的"你必须..."）。

### 🔴 场景 B：未检索到相关案例（或相似度极低）
- **触发安全降级 (Safe Degradation)**。
- **强制回复**: “抱歉，记忆宫殿知识库中暂未检索到与【具体事件】高度相关的历史处置案例。为确保合规，建议您直接请示当班值班经理。”
- **严禁行为**: 绝对禁止说出诸如“虽然没有案例，但我建议你可以...”这种话。

## 4. 🧪 冒烟测试用例 (Smoke Test Cases)

用于验证 RAG 召回精度与幻觉隔离机制的基准断言：

| 模拟查询 (Query) | 知识库状态 (DB State) | 预期输出关键断言 (Asserts) |
| :--- | :--- | :--- |
| "以前遇到游客中暑是怎么处理的？" | 存在 2 条中暑工单记录 | 必须包含历史案例的提炼步骤，且 structured_data 中 `retrieved_count` > 0 |
| "过山车停电悬停的应急预案是什么？" | 存在标准应急预案 PDF | 必须输出预案第一、二步，带预案名称引用 |
| "外星人把大门吸走了怎么办？" | **无相关记录** | 必须触发安全降级话术，`retrieved_count` = 0 |
