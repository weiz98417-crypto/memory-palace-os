# 设计决策

## 领域模型

监测信号 → 态势告警 → 运营事件。运营事件生命周期为 `DETECTED -> TRIAGED -> DISPATCHED -> ACKNOWLEDGED -> MITIGATING -> RESOLVED -> CLOSED`。告警可以自动恢复，运营事件必须由授权人员关闭。

## 运行时

模拟时钟支持播放、暂停、单步和倍速；基础 tick 为一秒，态势快照默认每秒刷新，信号按需每一至五秒产生。真实墙上时间另行写入审计记录。

## 存储与检索

PostgreSQL 是监测信号、告警、事件、任务、审批、回执和审计的事实源；Redis Streams 负责传输和队列；PostgreSQL pgvector 是唯一向量后端；本地 bge-m3 固定 1024 维；附件沿用现有安全存储接口。

## 连接器

离线 SVG/Canvas 景区作业地图是默认 Adapter；GIS/在线地图为可选 Adapter，页面展示接口能力、坐标系、图层和配置状态。内部系统接入环境是通知主渠道，短信和语音只保留可替换 Adapter。

## 入口与权限

景区指挥中心是正式工作台主入口；员工现场端和内部系统接入环境分别承担现场操作与渠道模拟。角色使用预置业务账号和独立浏览器会话，运行准备入口受保护且不出现在业务主界面。

## 实时协议

态势订阅使用 SSE，控制动作使用 HTTP，断线用事件序号和完整快照恢复，SSE 不可用时降级为短轮询。
