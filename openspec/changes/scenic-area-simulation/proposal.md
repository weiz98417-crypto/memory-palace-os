# 本地景区模拟环境

## Problem

项目已有应急 Agent、正式运营工作台和确定性 Demo 剧本，但缺少一条从景区外部态势到告警、运营事件、任务、审批、现场回执、复盘和组织记忆的连续真实业务动线。现有 Demo 控制器不应继续承担正式业务状态。

## Proposal

在正式 MVP 业务链路之上增加本地景区模拟环境：用可复现剧本和人工注入产生监测信号，用景区态势与事件引擎生成告警和事件，用 PostgreSQL + pgvector 保存事实与向量，用 Redis 传输实时变化，用 SSE 同步指挥中心、现场端和管理端。默认故事为“雨后观光车异常 → 东门客流上升”。

## Success criteria

- 一条垂直切片可从准备输入开始，经正式入口完成事件处置并形成审计卷宗。
- 指挥中心、员工现场端和内部通知渠道共享同一业务状态。
- 本机 CPU 可运行本地 bge-m3；GPU 可选加速。
- 外部 GIS、短信和语音以可见的可选连接器存在，不伪装生产就绪。
