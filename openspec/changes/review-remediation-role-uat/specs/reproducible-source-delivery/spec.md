# SPEC-05：可重复源码构建与启动

## Problem Statement

交付人员依照现有脚本可能调用失效入口，Python 约束互相冲突，前端构建可能解析到错误 pnpm 或要求本机先运行服务，导致源码包无法独立复建。

## Solution

让新终端及干净构建环境使用一致的依赖与入口完成四入口源码构建，再通过明确的依赖检查启动正式栈；环境缺失要报告真实原因。

## User Stories

1. 作为交付人员，我希望按文档能从源码构建，以免依赖开发者机器中的静态产物。
2. 作为开发者，我希望所有工具使用一致的 Python 下限，以免安装结果与运行结果不同。
3. 作为前端开发者，我希望子进程使用固定 pnpm，以免顶层命令正确但子命令版本漂移。
4. 作为构建人员，我希望契约检查不要求先启动 API，以便镜像可在干净环境构建。
5. 作为管理员，我希望启动不重复播种业务数据，以便安全重启。
6. 作为运维人员，我希望保留现有数据卷，以免通过重建环境丢失业务。
7. 作为交付人员，我希望缺模型缓存或 Secret 时收到明确错误，以便补齐环境。
8. 作为前端负责人，我希望四个入口都包含于构建产物，以免只交付部分新页面。
9. 作为运维人员，我希望健康与就绪区分进程存活和依赖可用，以便识别运行故障。
10. 作为验收负责人，我希望依赖版本记录可重现，以便把失败归因到实际构建。

## Implementation Decisions

- 复用正式应用入口、数据库初始化和现有部署命令，移除失效的快速启动引用；初始化幂等，业务播种为显式准备动作。
- Python 最低版本统一为 3.11，类型检查、格式化目标和镜像基线对齐。正式依赖及测试依赖应能在干净环境安装。
- Node 使用已确认的 24.15.x 基线，pnpm 固定 11.19.0，顶层与子进程一致；保留严格版本检查。
- 使用已有 OpenAPI 导出能力从真实应用导出契约，再作为文件输入校验生成类型；导出不连接业务数据库或调用真实模型。
- 继续冻结前端依赖安装；后端使用明确的依赖约束与可复现解析记录，不能把空壳锁元数据当成锁定完成。
- 源码交付构建四个正式入口并进入镜像；缓存/构建输出不成为源码事实源。
- 启动前检查 Docker engine、模型缓存、现有卷与 Secret 可用性。隔离 UAT 环境，禁止删除数据卷制造“干净启动”。
- 默认栈与完整栈遵守 SPEC-04；可选依赖关闭和已启用依赖故障分别报告。

## Testing Decisions

- 最高边界为公开构建/启动命令及正式入口响应，复用依赖锁测试、OpenAPI 导出测试、前端 lint/typecheck/Vitest 和 Compose 验证。
- 在不运行 8090 服务的环境验证契约导出、类型一致性与四入口构建。
- 使用固定工具链验证子进程版本；错误版本必须明确失败。
- 实际构建并启动默认/完整栈，重启后验证数据库业务计数未因重复播种增加。
- 环境不可用时记录阻断；静态 Compose 校验不替代运行态验收。

## Out of Scope

升级整个技术栈、跨所有操作系统的兼容承诺、新增离线产品能力、清空数据或发布生产环境。

## Further Notes

映射 R3；构建部分可独立实施，完整栈验收依赖 SPEC-02/04。联网源码构建是当前目标，已有可选离线交付策略保持不变。

## ADDED Requirements

### Requirement: 构建使用一致的版本约束
构建流程 SHALL 使用一致的 Python、Node 与 pnpm 基线，并验证子进程版本。

#### Scenario: 子命令解析到错误 pnpm
- **WHEN** 顶层构建已启动但子命令解析到不符合固定约束的 pnpm
- **THEN** 构建失败并报告版本差异，不通过关闭严格检查继续

### Requirement: API 契约可离线导出
构建流程 SHALL 在没有运行中业务服务时导出真实 OpenAPI 契约并检查前端类型。

#### Scenario: 本机 API 未启动
- **WHEN** 干净环境执行源码构建且本机没有 API 监听
- **THEN** 契约导出、类型检查和四入口构建能够使用文件输入完成，不需要真实模型凭据

### Requirement: 启动保持既有业务数据
正式启动 SHALL 使用有效入口与幂等初始化，MUST NOT 通过清空卷或自动重复播种解决失败。

#### Scenario: 同一部署重复启动
- **WHEN** 已有业务数据的部署再次启动
- **THEN** 正式入口可访问，已有业务保留且不产生重复业务样本

### Requirement: 环境失败如实阻断
运行准备 SHALL 明确区分静态配置合法与运行依赖可用。

#### Scenario: Docker engine 不可连接
- **WHEN** 配置静态校验通过但 Docker engine 不可连接
- **THEN** 运行验证报告 BLOCKED 及具体依赖原因，不生成 Live 通过证据
