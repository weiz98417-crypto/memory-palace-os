# SPEC-01：完整证据与封包门禁

## Problem Statement

验收负责人无法从“COMPLETED”判断完整业务是否真的通过：目前一条通过记录即可封包，空模型调用数组和空汇总文件可能逃过校验，旧运行或未提交修改也可能混入证据。

## Solution

提供可保存部分进度、但仅在完整验收通过后才能封包的证据合同。每个结果关联实际测试版本、角色、业务对象和真实运行记录，让内部验收结论可复核。

## User Stories

1. 作为验收负责人，我希望部分步骤可保存，以便执行中断后仍能诊断进度。
2. 作为验收负责人，我希望缺少任一必需旅程时不能封包，以免局部成功被当成全量通过。
3. 作为开发者，我希望失败包不可覆盖，以便修复后比较新旧运行。
4. 作为审计员，我希望能识别测试时的未提交改动，以便准确复现实际版本。
5. 作为审计员，我希望模型步骤必须有关联调用，以免空证据被判成功。
6. 作为知识负责人，我希望检索结果包含发布版本和场地，以便判断引用是否有效。
7. 作为运维人员，我希望恢复证据说明中断、领取及确认过程，以便证明任务没有丢失。
8. 作为安全评审人，我希望产物不含秘密和完整 Prompt，以便安全分享验收结果。
9. 作为验收执行者，我希望没有浏览器错误时允许空错误列表，以免为了通过校验制造无意义记录。
10. 作为发布负责人，我希望封包不要求先把正式注册表改为 READY，以免出现循环证明。

## Implementation Decisions

- 扩展既有 EvidenceRun、证据校验器与 UAT CLI；保持现有运行目录、步骤与产物模型，必要的合同升级必须显式版本化。
- 运行中检查验证已产生证据；完整封包验证固定的 E2E-00～16、UAT-F01～13 集合，拒绝遗漏、重复、未知步骤和非通过结果。
- 补充治理及浏览器覆盖证据通过独立产物引用表达，不伪造新的 E2E 编号；其完整性由 SPEC-08/09 验证。
- 封包要求主数据基线、真实业务关联、所有必需产物及校验和有效。记录 commit、工作区内容指纹、镜像摘要、依赖、运行环境、模型与向量基线。
- 真实模型成功步骤必须关联权威调用记录，验证 provider、deepseek-flash、is_mock=false、调用状态和 Agent 身份；预期故障步骤按其故障合同验证失败与恢复，不强求每次失败都成功调用。
- 八 Agent 可以在不同 trace 工作，通过同一 run 的事件、任务和经验来源链关联；消息受理四 Agent 仍须属于同一消息链。
- 模型、检索、数据库断言与队列恢复汇总需要实质记录；控制台错误列表允许为空。文件存在或 passed=true 不能替代业务证据。
- 失败 run 保留且不可改写为成功；修复后使用新 run。没有业务执行的来源采集失败也须如实报告。
- 不改正式注册表来满足封包；候选生成与提升由 SPEC-09 承担。

## Testing Decisions

- 最高测试边界是现有证据 CLI 的检查/封包行为：断言退出状态、诊断、持久产物和不可变性，不断言私有函数调用顺序。
- 复用既有 UAT evidence/journey 测试模式及临时证据包。
- 覆盖一条通过、29 条通过、重复/未知步骤、失败步骤、错误 run、旧模型、空必需记录、错业务关联、修改产物和秘密泄漏反例。
- 用合法完整固定证据验证封包结构；这些测试夹具不得作为 Live 验收证据。
- 真实执行后从数据库只读核对模型调用、业务对象和恢复记录。结构校验通过不宣称供应商调用真实发生。

## Out of Scope

实际业务旅程执行、秘密轮换、注册表提升、客户签收和持续运行验收。

## Further Notes

映射 R0；无实施依赖。规格状态 ready-for-agent，功能仍待验证。下游 SPEC-06～09 复用此合同，不另建证据格式。

## ADDED Requirements

### Requirement: 分离进度检查和全量封包
证据系统 SHALL 允许验证有效的部分进度，且 SHALL 仅在全部 30 个必需旅程通过时封包。

#### Scenario: 只有初始步骤通过
- **WHEN** 运行只记录了 E2E-00 的合法通过证据
- **THEN** 进度检查可以成功，封包必须失败并列出缺失旅程，运行不能变为 COMPLETED

#### Scenario: 完整集合有效
- **WHEN** 所有必需旅程各出现一次并通过，主数据和必需证据均通过语义校验
- **THEN** 系统记录完成时间并封包，后续重写或追加被拒绝

### Requirement: 校验实质调用与运行关联
证据系统 SHALL 按步骤合同核验真实模型、业务关联和产物内容，MUST NOT 仅凭空数组或声明状态判定通过。

#### Scenario: 生成式成功步骤无调用
- **WHEN** 生成式步骤声明 PASSED 但没有对应的真实调用或引用了其他 run 的记录
- **THEN** 校验失败并标明步骤与缺少的调用关联

#### Scenario: 控制台没有错误
- **WHEN** 浏览器执行已留存操作证据且错误列表为空
- **THEN** 系统接受空错误列表，不要求虚构错误记录

### Requirement: 可追溯且不可篡改的证据包
证据系统 SHALL 保存测试版本指纹、产物 SHA-256 和脱敏记录，MUST NOT 覆盖失败包或接受不匹配的产物。

#### Scenario: 运行产物被修改
- **WHEN** 证据文件内容与登记的 SHA-256 不一致
- **THEN** 校验和封包失败，既有结果保留并要求重新执行
